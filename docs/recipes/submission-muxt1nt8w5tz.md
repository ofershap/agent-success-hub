## המתכון המלא

המטרה
להחליף אתר עם הפניות, בדיקת לידים ודרך חזרה.

מה להכין
הכינו [אתר ישן], כתובות, תכנים, יעדי טפסים, מדדי בסיס, גישה מורשית לאחסון ולדומיין ואישור נפרד לפרסום.
Git
Backup
HTTP checks
Browser
Search Console
ממלאים [כלי], [חשבון], [יעד] ו[בעל סמכות] לפני עבודה. גישה אינה רשות לשנות, לשתף או לשלם. כסף, מסירה לאדם אחר ופרסום דורשים אישור נפרד של המצב הסופי.

השלבים
1. אספו כתובות ממפת אתר, סריקה ונתוני חיפוש. סמנו דפים חשובים ותנועה קיימת. שמרו גרסה ומדדי בסיס.
2. גבו קבצים, מדיה, מסד נתונים והגדרות. בדקו שניתן לקרוא ולהחזיר את הגיבוי. שמרו מחוץ לנתיב ציבורי.
3. בנו מפת ישן מול חדש. שמרו כתובות כשאפשר. כתובת שהוחלפה מפנה בקביעות ליעד מתאים, לא כולן לדף הבית.
4. בנו סביבת בדיקה חסומה לאינדוקס. בדקו תוכן, כותרות, כתובת קנונית, קישורים ומפת אתר. אל תשנו מחירים או הצעות בלי אישור.
5. בדקו כל הפניה: קוד, יעד סופי, לולאה ושרשרת. בדקו טפסים ביעד שאושר. תעדו חריגים.
6. קבעו תנאי חזרה, אחראי וגרסה מדויקת. תרגלו שחזור בטוח. הציגו בדיקות וקבלו אישור למעבר.
7. אחרי פרסום קראו את הגרסה החיה. בדקו בטלפון ובמחשב והוכיחו הגעת פנייה ליעד המאושר.
8. בדקו דפים חשובים בכלי החיפוש. השוו שגיאות, אינדוקס ותנועה באותם חלונות זמן. כשל קריטי מפעיל חזרה.

הבדיקות
גיבוי קריא. שחזור נבדק. מפת הפניות שלמה עם חריגים. גרסה חיה נכונה. טופס הגיע ליעד. תצוגה נבדקה בשני גדלים.

המגבלות
מעבר טכני אינו הוכחת שימור דירוג או תנועה. מפת אתר שהתקבלה אינה הוכחה שכל הדפים מאונדקסים. שינוי באחסון מחייב בדיקה מחדש.
